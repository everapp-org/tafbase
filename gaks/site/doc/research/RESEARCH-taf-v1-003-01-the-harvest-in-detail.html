The full evidence behind RESEARCH-taf-v1-002-01: every idea recovered from the previous-generation framework (a Maven multi-module Java/Selenium/Cucumber/Appium suite — tests_base engine plus per-product modules), with the file that proves it, the translation to generated code, and where it landed in this corpus.

Architecture context: JUnit4 + Cucumber 7.13 + Selenium 4.35 + Appium. A prior generation exists underneath (Concordion + a TSV interpreter — item 14). → marks the tafbase landing: a CONCEPT page, a lane of PLAN-taf-v1-001-01, or done.

Per-step pacing / dwell#

1. visibilitySleep / visiSleep — the global dwell#

  • Evidence: tests_base/.../utils/TimeUtils.java:478-498; config visibility.sleep.time=222 (config.properties:32); mutable static Configuration.VISIBILITY_SLEEP (utils/Configuration.java:60,192). Called before and after nearly every action (com/fxcm/qa/TestBase.java:809-826).
  • What it is: a Thread.sleep wrapper with two units and a zero-arg overload using the global. Two purposes: let JS/animations settle, and make live-watching pleasant (paired with the Overlay). Overridden per call-site (visiSleep(345) at TestBase.java:1082), per run (config), at runtime (non-final static; even inside JS — setTimeout(()=>arguments[0].click(), VISIBILITY_SLEEP) at TestBase.java:756,789).
  • Translation: a DSL-level annotation, not a sleep — resolved at codegen into per-step literals.
  • Cost: small. → done — {"dwell": <ms>}; CONCEPT-dsl-v1-003-01-the-dwell.

Browser/driver factory#

2. "Resolution" — one token drives local emulation AND BrowserStack#

  • Evidence: CucumberTestBase.initTest dispatches on "desktop, mobile, tablet".contains(resolution) (:139-143); local mobile/tablet via CDP Emulation.setDeviceMetricsOverride (:550-572); remote via token parsing — w10_chrome, iPhone16Pro_safari, GalaxyS25Ultra_samsung → os/osVersion/ deviceName/browserName switch (:319-430). Env creds override browserstack.yml (:289-290); buildIdentifier=TEST_RUN_ID, sessionName=testName_example (:306-307).
  • Translation: already a mini-DSL — device: Pixel9ProXL_chrome emits the exact capabilities object; zero runtime parsing, compile-time vocabulary.
  • Cost: medium. → lane K-11; CONCEPT-dsl-v1-012-01-the-target.

3. Tag → environment → URL AND locator-version selection#

  • Evidence: isUatTest maps @qa_env/@uat_env/@browserstack_* to suiteName + testUrl + DEFAULT_VERSION (CucumberTestBase.java:128-134,218-239; DEFAULT_VERSION_QA/UAT in Configuration.java:28-29,139-148).
  • Translation: env: bakes baseUrl + locator version into the emitted suite.
  • Cost: small. → lane K-11; same concept as item 2.

Reporting & debugging#

8. teststepFail — the single funnel for failure#

  • Evidence: TestBase.java:1666-1691 — appends exception line number, shows message, calls breakPoint(), saves DOM, screenshots (Robot local / TakesScreenshot remote), then fails. Called by step defs (PortalStepdefs.java:1398).
  • Translation: generated failure hook — DOM + screenshot + structured record.
  • Cost: small. → done in part — the pytest hook files DOM+URL; CONCEPT-testing-v1-002-01-the-failure-funnel.

9. Screenshots as golden standard — grammar + approval loop#

  • Evidence: grammar TestCaseId_RunId_Resolution_StepId_{Expected,Actual,Diff}.PNG (utils/screenshots/domain/ScreenshotName.java:7-18); capture + compare in ActionsBase.compareImages (:1052-1163) — _Expected_ALT.PNG alternates, REPLACE_DELETED_SCREENSHOTS reseeds, IGNORE_MISSING_SCREENSHOTS soft-skips; per-device excluded regions (notch, status bar) + pixelToleranceLevel(0.4) + DYN-in-name → looser minimalRectangleSize=1300 (screenshots/TestBaseScreenshots.java:316-357); scan → group → Thymeleaf HTML (infra/ResultsScanner.java, infra/ThymeleafReportRenderer.java); promotion via selection file + auto-generated commit message (app/ApplySelectionUseCase.java:36-76,140-162); CLI cli/ScreenshotToolMain.java.
  • Translation: compare screen step + taf promote.
  • Cost: lane-sized. → lane J-10; CONCEPT-testing-v1-003-01-the-golden-file.

The prior-generation DSL — tafbase's ancestor#

14. HappyPathBase — the TSV interpreter#

  • Evidence: screenshots/HappyPathBase.java:104-349 (the whole interpret() commented out). Columns (:58-67): scrId | step | action | fieldCanonicalName | label | value | scrControl | transLabel | transValue | jiraTicket. Actions: Action, WaitHeader, WaitH1, WaitH2, CheckFlavicon, CheckLink, HandleLocale, SetParameter, SetParamLabel, DoStep. scrControl toggled screenshot per line; transLabel/transValue ran one row against localized UIs; jiraTicket linked the step.   • Translation: read as a requirements doc — the column model is a field-proven DSL grammar; codegen is its compile-time heir.
