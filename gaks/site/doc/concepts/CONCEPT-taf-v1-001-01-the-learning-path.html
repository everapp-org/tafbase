Definition#

The ordered index of this corpus's concept documents, junior-first. The corpus is flat and wiki-linked; this page is the sequence a reader new to test automation can follow, each entry naming its prerequisites.

Why it exists#

ADR-taf-v1-002-01 makes the delivered project a learning surface: every concept the generated code embodies is a page here, and generated files cite their concepts with @concept lines the checker enforces. This page answers "where do I start?"

The domains#

The path is the on-ramp; the corpus is grouped by what a page teaches:

domain teaches
python the language surface — venv, env-adjacent mechanics
pytest the test runner — fixtures, hooks, scope
playwright the browser library — locators, contexts, waiting
java the second emitter's world — JUnit lifecycle, Maven
pom the page-object model — organizing a suite
testing the discipline — AAA, failure handling, goldens, flakes
dsl the model language — steps, locators, targets, walks
taf the framework itself — its contract, sinks, artifacts

A concept files under the domain it teaches; language-neutral ideas — the TAF_* contract, the run layout — live under taf, once, never duplicated per language.

Three readers, three entries#

tafbase is three levels — build the framework, model a SUT, use the suite (CONCEPT-taf-v1-007-01-the-three-levels). Each reads a different subset:

you are read first
a model author dsl — the model, the step language, waits, locators
a test user taf + testing — the contract, the sink, failure handling
a framework contributor python + pytest + playwright — the machinery

A reader never needs all domains — that separation is the DSL First promise itself.
